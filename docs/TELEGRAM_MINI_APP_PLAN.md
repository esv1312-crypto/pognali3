# Погнали — Telegram Mini App: план переноса

Статус: проектирование и аудит перед реализацией. Исходная ветка: main. Рабочая ветка: feature/telegram-mini-app.

## Продуктовое решение

Telegram Mini App становится первым доступным каналом продукта, но не отдельным параллельным продуктом. Сохраняем философию: «увидел событие → выбрал → присоединился → пригласил → пошёл в реальную жизнь».

Не превращаем продукт в классическую социальную сеть: никаких бесконечных постов/лайков как главного сценария. Интерфейс — разговор + быстрые карточки событий + карта по запросу.

## Обязательные функции

- Авторизация через Telegram Mini Apps initData с обязательной серверной проверкой подписи и срока актуальности; не доверять данным пользователя, присланным клиентом.
- Профиль пользователя и настройки видимости/локации.
- Лента и поиск событий: дата/время, категория, расстояние, район/город, доступные места.
- Карта с маркерами событий, выбором точки/района и переходом к карточке события.
- Карточка события: организатор, описание, место, время, участники, лимит, правила и действие «Погнали».
- Создание и редактирование события, присоединение/выход, список участников.
- Приглашения через Telegram deep links и отправку в личные/групповые чаты.
- Коммуникация по конкретному событию; уведомления от бота.
- Фото/аватары, состояния загрузки/ошибок/пустых результатов.
- Жалоба/блокировка пользователя и события, базовые антиспам-ограничения.
- Политика конфиденциальности, условия использования, удаление аккаунта/данных и понятные разрешения.

## Геолокация: VPN и прокси

VPN/Telegram-прокси сами по себе не подменяют GPS-координаты телефона. Они меняют сетевой маршрут и часто IP-адрес, поэтому геолокация по IP может указывать на другую страну/город. Нельзя использовать IP как основной источник координат.

Рекомендуемый порядок:
1. В Mini App запросить геолокацию устройства через поддерживаемый Telegram LocationManager (после явного действия пользователя и разрешения).
2. Если LocationManager недоступен в конкретном клиенте Telegram, использовать стандартный Web Geolocation API при наличии поддержки и разрешения.
3. Если не сработало — предложить отправить геопозицию отдельной кнопкой бота request_location в личном чате.
4. Всегда дать ручной выбор города/района и возможность двигать точку на карте.
5. Показывать рядом с событием его публичное место; не публиковать текущие координаты пользователя другим людям без отдельного согласия.
6. Не требовать постоянного фонового отслеживания. Хранить только необходимую точность/срок; пользователь может удалить или изменить местоположение.

Нужно проверить доступность API и разрешения на реальных клиентах Telegram для Android/iOS/Desktop, в том числе при VPN и прокси. При сетевых ограничениях карта и геокодер должны иметь обработку ошибок и альтернативный ручной сценарий.

## Карта и геоданные

- Выбрать провайдера карты/тайлов/геокодирования после проверки покрытия и доступности в России и за её пределами, условий лицензии, стоимости и ограничений.
- Не привязывать бизнес-логику к одному провайдеру: интерфейс карты должен иметь адаптер/слой данных, чтобы заменить карту без переписывания событий.
- Координаты события — часть серверной модели; фильтрация по расстоянию выполняется сервером, если backend это поддерживает.
- Если тайлы или геокодер недоступны, показывать список событий и адрес/ссылку на внешнюю навигацию.

## Предлагаемая структура интерфейса

- Главный экран: поле «Куда хочешь?», быстрые категории и подборка событий.
- Вкладки/разделы: «События», «Карта», «Мои планы», «Профиль».
- Диалоговый сценарий для поиска и создания: пользователь пишет естественным языком, приложение задаёт только необходимые уточнения и переводит намерение в реальные фильтры/форму.
- Карта не обязана быть постоянно открыта: открывается по запросу или из карточки события.
- Все ключевые действия доступны обычными кнопками; чат не должен быть единственным способом навигации.

## Технический порядок работ

1. Аудит текущего docs/index.html, текущей логики событий и наличия/отсутствия backend/API.
2. Зафиксировать матрицу функций: работает сейчас / частично / заглушка / отсутствует.
3. Определить источник истины для данных. Не считать локальное хранилище браузера полноценным backend для нескольких пользователей.
4. Реализовать Telegram-совместимый frontend и серверную проверку Telegram initData.
5. Реализовать/подключить постоянное хранилище, события, участников, приглашения и права доступа.
6. Подключить геолокацию с каскадным fallback и провайдер карты после тестов доступности.
7. Добавить бота, меню Mini App и deep links на события.
8. Протестировать сценарий двумя и более аккаунтами на Android/iOS, с VPN/прокси и без них.
9. Выпустить тестовую версию, собрать обратную связь, затем расширять.

## Критерии готовности

- Пользователь может найти или создать событие, присоединиться, пригласить друга и открыть место на карте.
- Данные одинаковы на разных устройствах и между пользователями.
- Входные данные Telegram проверяются на сервере.
- VPN/прокси не ломают определение GPS; при отказе разрешений работает ручной выбор города/района.
- При недоступной карте пользователь всё ещё может пользоваться списком событий.
- Основные сценарии проверены на реальных Telegram-клиентах и задокументированы.
